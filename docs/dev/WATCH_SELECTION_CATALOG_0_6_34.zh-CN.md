# 具体手表选择、连接确认与完整训练目录

配套版本：Android 手机 1.6.31（77）、vivo WATCH GT 方屏 0.6.34（49）。圆屏仍是 0.6.31 旧兼容包，不具备本次新增协议。

## 官方依据和平台边界

2026-11-19 再次查询官方 release API，最新发布仍为 [v1.4.5](https://github.com/DuarteSantos8/openGym/releases/tag/v1.4.5)，发布时间 2026-11-14。核对上游提交 `2d70e026effc6602f513555166a97443520f0572` 的 `frontend/src/lib/watch-sync.js` 中 `buildReady`：按 `effectiveRoutineIds` 取得今日计划；今日多个计划按排期顺序组成一次会话，每条动作带来源 `rid`；其余计划单独提供。官方 Wear OS 设置区分配对节点、应用可达性和最近手表回应。Google Data Layer 的节点接口不能直接移植成 vivo 绑定设备接口。

实际检查随项目分发的 `frontend/android/app/libs/device-rpc.aar`：`DeviceRpcManager` / `Request.Builder` 没有列举全部已绑定手表或指定 deviceId 切换物理通道的方法。它通过 vivo 运动健康当前设备通道通信。本次因此提供：

- 在运动健康完成硬件绑定；手机列出曾向本手机 OpenGym 报告安装身份的具体手表。
- 用户明确选择一块，保存于本机 `opengym_blueos_devices_v1`，不随云账户同步到另一台手机。
- 相同设备名用身份尾号区分；这是应用安装身份，重装手表应用会产生新身份，不是硬件序列号。
- 发现另一块手表不会自动改变选择。需要切换物理连接时打开 vivo 运动健康。
- 旧版手表没有该安装身份握手，不能假称它支持新版具体设备选择和目录确认。

## 代码链路

### 选择与连接

`WatchIntegration.jsx → watch-link.js → WatchRpcPlugin.java → DeviceRpcManager / vivo 运动健康 → rpc.js`。

`watch-devices.js` 校验和维护最多 12 个曾连接身份；`selectWatchDevice` 重置本目标的同步基线，旧设备的持久任务保留在各自文件，不跨设备移交。已有训练或待处理事务时禁止切换已有目标；首次选择不被等待中的手机训练阻塞。

手机发送的业务消息外层带 `targetInstallationId`；手表接收先检查目标，去掉路由字段后再核验冻结业务数据。手表发送外层带 `sourceInstallationId`；已有业务事件自身的 `installationId` 仍保留。手机仅处理所选来源的事件和业务收据。原生 Inbox 读取按所选身份过滤，其他手表的记录保留，不能占满当前设备的前 32 条批次。

连接状态分为：运动健康 SDK 通道、识别到的当前应用身份、所选应用的新鲜双向确认。手机发送本次唯一 `link_probe`；仅同来源、同 requestId 的 `link_probe_ack` 能确认在线。5 秒超时，确认 15 秒后失效；断连立即失效。重放旧 hello、发送成功和旧探测回复均不算在线。设置面板可见时每 5 秒检查，隐藏后不发新探测，卸载时清理监听和定时器；周期检查不反复触发 hello 和全量同步。

### 全量与今日目录

`App.jsx → watchCatalogOf → pushWatchCatalog → persistentSender(catalog) → RPC → persistentReceiver(catalog) → writeStoredAtomic(plan_catalog) → Index.onCatalog`。

- 枚举全部 `S.routines`，不再按旧设置只发送今日和一个额外计划。
- 今日按有效排期、指定日期和原顺序选择；多个今日计划合并，保留 `routineIds` 和动作 `rid`。
- 首页“今天”展示组合计划；下方按官方分类展示非今日计划。无今日安排时仍能从其他计划开始。
- 删除、空目录、计划修改、单位、体重、年龄、强度、器械重量设置、语言及本地日期变化都会触发相应目录重建。未变化目录去重。
- 首页仅把 id、名称和显示统计放入响应式数据；完整 entries/rows 留在 staticData 模型，避免列表响应式遍历整套训练对象。
- 今日日期过期后撤下“今天”卡片，离线计划库继续可用。日期跟随设备本地时间；时区不一致应校准设备时间。

### 持久传输和失败语义

复用已存在的选择性 ACK 分片协议，增加独立 `catalog` 命名空间；训练 `sync` 队列与目录队列互不覆盖。发送文件由通道及安装身份的 SHA-256 区分。训练状态和业务收据优先，目录在其后推进。

目录与训练均按分片保存、断点恢复、校验、重试和退避。完整目录保存成功后才发布页面更新及 `applied` 收据，手机收到精确收据才显示“手表已保存”。存储失败保留发送任务，不以 SDK 返回成功冒充目录成功。旧 stamp 不覆盖新目录；相同 stamp 不同校验和拒绝；保留较新目录时手机不能把本次旧目录标成已应用。

协议保守上限仍是每个传输 128 KiB / 最多 132 片，不是宣称硬件固件的极限。超大目录会明确报错，绝不静默截断成部分计划；当前没有无限容量或跨多个目录事务的承诺。不要把“全量”解释为取消手表资源边界。目录确认后断连，手机仍可显示上次保存事实，但连接状态单独失效。

另外修复 hello 协调器与首次训练推送的竞态：被同会话较新快照替代的发送不再被当成失败重新排队，避免业务收据之后重复全量推送。

## 验证与真机验收

自动回归包含：具体身份明确选择、同名不同身份、拒绝别表消息、首选不被活动训练阻塞、精确探测及过期、目录独立持久通道、保存失败后重试、整包应用后才确认、旧 stamp 保留、空目录、今日多计划来源和顺序、跨午夜失效、页面计时器清理。完整前端、移动启动、翻译一致性、移动生产包、BlueOS 编译模板布局检查与签名包核验均在发布前执行；实际结果见对应发布的 CI。

真实 WATCH GT 尚需执行：

1. 在运动健康分别切换两块已绑定手表，每次打开 OpenGym；核对列表、尾号、显式选择和“当前另一块手表”提示。不要靠改选项文字推断物理连接已切换。
2. 保持 SDK 通道连接但退出目标手表应用，确认探测超时，不应继续显示实时在线；重开后刷新确认。
3. 推送多个计划、当天两个计划、无今日计划和空计划库；核对数量、顺序、来源、删除与离线启动。
4. 同步中断开、重连和重启两端，验证恢复；使用测试设备模拟磁盘失败，确认无虚假的保存成功。
5. 正在训练时持续改重量/次数、完成组、休息倒计时和切页面，确认业务事件优先且目录不会反复开始；连续 30 分钟采集真实操作延迟、卡顿、内存和崩溃日志。
