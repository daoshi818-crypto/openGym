# OpenGym 1.6.25 / BlueOS 手表 0.6.28

修复圆点切组排队后无法完成，以及未保存的休息预览覆盖手机权威状态的问题。本版不调整界面布局，不增加训练同步命令，不改变持久化事件去重、重试和手机裁决规则。

## 根因与修改

- 圆点切组使用 120ms 合并窗口，但把 async flush 直接传给了定时器。本地 BlueOS 原厂 SDK framework.js（COMMITID 7af9d62）的桥接序列化只为普通 Function 注册 callback ID，AsyncFunction 没有有效回调。因此圆点停在 pending，完成按钮的防误操作门持续拦截。改为普通函数回调包装异步处理，合并与持久化边界保持原样。
- 对照用户两次导出，2026-11-12 15:52:37（UTC+8）出现 dot_tap、dot_queued，此后直到第二次导出都没有 dot_commit_begin；两次 droppedInteractions=0。原厂序列化验证及真实页面的 SDK 定时器回归均可复现旧代码失败。
- 用户补充“手机完成第二组后手表进入休息，休息结束回到第二组，按钮变成撤回且不能点击”：完成状态能下发，撤回同样被未释放的圆点 pending 门拦截。新增完整回归验证该场景下撤回可用，并能继续圆点选择第三组和完成。
- 另一个可复现的页面缺陷：表冠休息调整尚未落盘时，bindRpc 和 onSyncUpdate 会把旧预览覆盖到手机的新休息状态上。现在预览必须仍属于相同 sid/restId/restVersion 基准；手机跳过、调整或开启新一轮休息后取消旧预览；相同基准回声仍保留本地预览。已接受的持久化事件仍按原协议处理。
- 增加 page_sync 的休息截止、休息版本、表冠预览和圆点待处理标记；页面回调异常记录为 page_sync_error。sync_applied 仍只代表持久化接收，不伪装成画面更新成功。继续使用最多 64 条、24KB 的独立日志，不增加训练队列写入。
- 页面同步记录归为通信证据，不占用点击/本地提交的预留份额；下行更新洪峰不会因为新增日志而挤掉圆点证据。

## 证据边界

用户第二段描述按“手机完成进入休息，再从手机跳过，手表未跟上”检查。15:53:41 与 15:53:44 的下行传输均有持久化确认，但现有导出没有其 rest 载荷和页面采纳结果。15:53:46 之后成功确认的 rest 是手表上行，不能据此宣称手机跳过已在手表显示。日志也不能证明用户当时操作过表冠；休息预览覆盖是新增回归确认的独立缺陷，不强行认定为该次唯一原因。

## 验证与复测

新增原生桥接回归同时执行真实切组模块和 Workout 页面代理，验证切组→完成→跳过可继续；覆盖手机完成→休息→跳过、预览未保存、新休息轮次、相同基准回声保留，以及页面回调失败与持久化确认分开记录。普通 Node 定时器允许 async 回调，不能单独证明 BlueOS 兼容。
