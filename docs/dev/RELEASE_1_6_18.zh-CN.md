# openGym 定制版 1.6.18

手机 **1.6.18 / code 64**，手表 **0.6.21 / code 36**（方屏、圆屏）。请双端一起升级；保留现有数据，不要清空未确认操作。

## 训练操作本地优先
- 完成/取消组、重量次数、强度、休息、焦点、暂停使用同一候选文档保存训练结果及稳定待发事件，落盘后再刷新成功状态并后台上传。
- 保存失败不显示已保存；慢写期间的新输入、心率和快照不能被旧页面覆盖。
- 本地结束先冻结关闭日志、先决操作和最终汇总；日志可靠后可离开，恢复不依赖手机立即确认。

## 可靠同步与传输调度
- 独立字段操作可绕过失败事件退避；同字段、多字段、休息/焦点/结构/结束按显式依赖和字段版本处理。
- received 与精确 committed 保留；传输成功不清业务。冲突及依赖载荷先归档，容量满则保留待处理数据。
- 手表与手机原生所有实际 RPC 发送走单门禁，控制、业务和快照有优先级、公平性、超时和旧连接回调隔离。
- Coordinator 只登记快照任务，不等待整份快照传完。
- 协商后启用持久化选择性分块：丢块只补未确认块，双方重启恢复相同内容和进度；取消精确落盘并确认后重建完整快照。
- 保留旧 v2、旧 v3；新扩展必须分别协商。新持久化路径当前仅使用完整快照，不宣称实现持久化 Delta 优化。
- 修复同毫秒不同 eventId 的编辑被旧时间戳去重误吞的问题。

## 验证与限制
- 自动化涵盖本地存储失败、立即重启、ACK 丢失、依赖冲突、关闭日志恢复、20 块故障续传及门禁公平性。
- 主机模拟性能与真机测量严格区分；本次未连接真实 BlueOS 手表，不能承诺所有固件上的通信、卡顿和闪退均已解决。
- 存储/发送超时是逻辑超时，固件迟到的物理写入无法由 JS 真正取消，仍需真机断电和后台存活验证。
- 协议、容量和保留边界见 watch-app/SYNC_PROTOCOL.md，实施审计和性能样本见 docs/dev/SYNC_REFACTOR_1_6_18.zh-CN.md。

安装对应屏型 RPK；不改视觉布局，不恢复动作演示，不更换 DeviceRpc/BlueOS Interconnect。
