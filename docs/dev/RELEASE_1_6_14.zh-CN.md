# openGym 定制版 1.6.14

手机 versionCode 60。本次修复 AI 教练普通聊天的 `invalid notes` 兼容问题；不是单纯修改文案，也不需要改用“复盘训练”来发起组数调整。

## 修复内容
- 部分仅支持 JSON mode 的模型会把 `notes` 返回为单个字符串，而应用原来只接受字符串数组，导致整份回复被拒绝。
- 对单段文本做无损数组包装；缺省/null/空白按无备注处理。对象、嵌套数组、非文本和超限内容仍拒绝，不解析备注中的指令。
- 聊天提示词明确完整 JSON 字段类型；schema 明确备注最多 10 项、每项 1200 字符；异常反馈明确正确类型，便于模型修复。
- 继续保留组数 1–10 的整数限制、动作身份/计划范围检查、新鲜状态与修订校验；任何建议都必须经过确认才应用，不自动修改正在训练或历史记录。

## 真实 API 验证
在用户授权下，用合成计划直连 DeepSeek 官方 API，不发送用户真实训练记录；密钥不进入源码、配置、报告或测试夹具。

- 实际捕获到单字符串 `notes` 被旧校验拒绝的同类错误；这不是每次请求都出现的问题。
- 修复后，测试时模型列表中的 `deepseek-flash` 和 `deepseek-v4-pro` 各跑 3 个场景：原始要求、两次失败后的追问、带复盘上下文的要求，共 6 个场景通过产品回复校验。
- 原话“我想把练背除了第一个动作以外 其他改为三组”：两个模型均生成三项修改，保留首动作 4 组，其余三个由 4 组改 3 组；另一份练胸计划不变。
- 官方 endpoint 在本次测试中拒绝 JSON Schema 模式（HTTP 400），现有适配器自动降为 JSON object（HTTP 200）。这不是需要用户重新配置的 App 报错。
- 对“为什么也提示这个”的追问，一个模型返回可读说明，另一个返回待确认修改方案；不承诺每条追问都强制生成计划。
- 把 8 份已脱敏的真实模型输出加入离线回归，包括曾触发错误的单段备注，重放产品 pipeline、pending、显式确认与应用链路。模型原始响应不能自行授予应用权限。

## 升级与边界
- 手机安装本次 APK 即包含本地 BYOK 的校验与提示词修复，不需要先改训练数据。
- 手表没有代码变化，发布继续附带 **0.6.18 / code 33** 方屏和圆屏包。已安装 0.6.18 的手表无需重复安装。
- 这是合成数据的真实 API 测试与自动化应用验证，不冒称验证了用户手机的键盘、设备布局或全部真实账号配置。
