# 长按结束可靠性与首页连接提示

对应手机 1.6.35（81），390×450 方屏 0.6.38（53）。

## 可复现的问题与修正

1. `Workout.startFinishHold()` 在同一次接触收到重复 start 时重置长按截止。回归通过故意重复 start 复现原实现未能按时完成；现在忽略重复 start，并用代次隔离已经取消的回调。
2. 单次截止回调丢失时，原 interval 只绘制百分比，不执行完成。故障注入回归复现该路径；现在进度到期和抬手也会校验绝对截止并完成一次保存。小于一秒、触控取消、滑动和隐藏仍不会保存。
3. `Workout.onEnd()` 的 `localCommitPending` guard 会静默丢弃结束请求。原先的组操作正在等待写盘时可复现。结束改为进入同一条 session_state 原子队列；`session.commitSessionAction()` 在入队前拦截关闭后新提交的工作，在执行阶段根据持久 closeIntent 拦截，保留关闭前已经入队的动作。
4. 本地关闭成功后同步逐条 `sendEvent()`，会在按钮路径集中序列化 outbox；异常还会阻止导航。现在先完成本地关闭并导航，再通过 App 定时器启动既有分批回放。`rpc.replayPendingEvents()` 同时读取活动训练和持久关闭日志，页面销毁不影响 App 回放。
5. 原 `rpc.flush()` 会绕过分批逻辑，同步补齐所有关闭事件。新增真实 session / close-journal / RPC 集成用例复现单轮入队八条；现在缺失关闭日志共用每批两条的回放。队列拒绝整批时结束快速循环，依赖正常重试周期继续，保留原日志。已经存在业务决定的 eventId 不重复入队，旧 ACK 兼容用例同时覆盖。
6. 关闭意图已持久但 journal、closed_sessions、summary_last 或清空活动训练失败时，原 Page 仍持有旧状态。现在采用最新冻结状态，停止时钟和休息输入等继续写入，禁止取消或换成另一种关闭决定，保留原有结束控件重试；复用已冻结 eventId、组记录和汇总。尚未持久冻结的失败不限制继续或放弃。
7. `Workout.tickSyncStatus()` 不再渲染连接文字。仅首页 `Index.updatePhoneLink()` 保留连接确认；训练页保留待上传、待确认和存储错误，无内容时隐藏空状态行。结果页“已本地保存／待手机确认”仍是业务保存回执。

这些是源码和故障注入中已复现的缺口，不能据此认定它们是实机卡住的全部原因。

## 回归与预览

主要用例：`frontend/src/lib/watch-finish-hold.test.js`、`watch-local-transaction.test.js`、`watch-backlog.test.js`、`watch-receiver.test.js`。长按测试执行真实 .ux 脚本，并模拟原生 Page 绑定方法、强对象代理和 raw staticData；RPC 用例运行实际持久化、关闭日志、事件编号与通信逻辑，仅替换硬件 API。

检查短按、重复开始、丢截止回调、延迟回调、触控取消、隐藏、组操作在途与排队、四种收尾写入失败、丢存储回调后重试、迟到回调、传输异常和满队列。通过编译模板与 SDK 字体增加保存中、冻结重试场景的 390×450 语义预览，检查按钮、文字裁切与滚动可达。原生编译与签名另行验证。

## 真机验收

1. 覆盖安装配套版本；确认首页显示连接状态，训练概览、当前组和统计页面不重复显示连接文字。断开手机后训练页仍可操作，出现待上传时只显示待传数量。
2. 在训练概览按住结束一秒；测试中途松手、滑动、系统触控取消、息屏，以及连续多次短按。短按不结束，有效长按仅保存一次，进度不会停在 70% 或 100%。全部完成弹窗的长按也重复同样操作。
3. 完成一组后立即长按结束；分别在休息表冠调整后、重量次数调整后、长待传队列中操作。保存历史应包含最后已提交的组和数值，不等待手机上传才显示结果。
4. 手机断连、杀掉手机应用或模拟传输失败后保存，再退出训练页、重连及重启应用。待传记录应继续补传，手机历史只产生一条，业务确认前不显示已同步。
5. 在具备故障注入条件的开发设备模拟存储失败或缺少回调：未冻结时仍能保留原训练或放弃；已冻结时显示保存重试，不能通过继续训练或另选放弃覆盖原记录。恢复存储后重试应复用原记录。
6. 连续保存与重连、切换页面并运行 30 分钟，采集原生日志，检查是否仍出现触控丢失、存储回调异常、后台任务累积或真实死机。没有设备采样，不填写实测延迟、FPS、内存峰值或稳定性结论。
