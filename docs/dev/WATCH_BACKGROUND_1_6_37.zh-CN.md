# WATCH GT 留存与无操作回表盘专项

对应手机 1.6.37（83）、390×450 方屏 0.6.40（55）。用户最终澄清的症状是没有主动操作时自行返回表盘，不能仅按手动切换应用处理。

## 官方依据与边界

1. [后台运行](https://developers-watch.vivo.com.cn/reference/extend/resident/)：切换到后台通常暂停；持续运行要求 manifest 声明后台接口，且至少一个已声明接口正在工作。公开表列出音频、录音、上传下载、定位和 BLE 连接；同时要求后台接口导入和工作放在 app.ux，减少页面切换/销毁影响。当前使用的 health 与 BlueXLink 不直接出现在该公开表中，不能仅凭心率订阅、普通计时器或任意添加 features 宣称无限常驻。本版未为保活而增加不属于训练业务的音频或定位。
2. [定时任务](https://developers-watch.vivo.com.cn/api/system/schedule/)：`@blueos.app.appmanager.schedule`；type=2 的 timeout 是真实流逝的毫秒间隔，休眠也计算；triggerMethod 指向 app.ux 方法。不提供 interval 时不周期执行。返回或 success 回调提供原生任务 ID，cancel(id) 取消任务；-27 为任务已满，-28 为已注册。
3. [屏幕亮度](https://developers-watch.vivo.com.cn/api/system/brightness/)：`setKeepScreenOn({keepScreenOn})` 允许控制保持亮屏。本版仅在有未暂停、未冻结的活动训练且 App 在前台时申请；保持亮屏会增加功耗，不将亮屏成功当成进程不会被终止的证明。
4. [应用管理](https://developers-watch.vivo.com.cn/api/system/am/)：moveTaskToBack 是主动移到后台，需要 AM 权限；用户没有主动操作，本版不将该接口当作本症状的修复手段。

上述官方页面与 page-data JSON 已保存在本轮本地诊断目录。公开 SDK 语言元数据确认 schedule 的 scheduleJob/cancel 以及 brightness 的 setKeepScreenOn 对 watch 未标记排除。编译通过仍不能代替具体 WATCH GT 固件的实际行为验证。

## 证据与实现

- 旧 `Workout.setRestScreenLock()` 根据休息状态多次释放亮屏，活动训练的非休息阶段没有统一保持策略。`app.ux` 新增 App 生命周期控制器，训练页将屏幕控制委托该所有者。页面之间不再分别覆盖训练前台的策略。
- 旧 app.ux 只有创建、销毁处理，隐藏时未立即请求 HR 检查点，也没有 OS 级训练任务。现在 App 负责恢复通信、会话 HR、任务注册；onHide 请求 flushHr，onShow 重新读取持久状态。
- `lib/training-runtime.js` 只保留训练身份、分段和状态标量。每次注册一个 60 秒后的单次任务；任务参数和已持久元数据都匹配时，才进行检查点并续约。注册失败、持久化失败、迟到回调、读失败和重复任务均有守卫。空闲首页、暂停、关闭或过期训练不续约。
- `lib/persistence.js` 在 session_state 的原子或普通写入成功后通知控制器，以该次已确认的候选为依据，不把未确认的暂停当作成功。心率计数变化但身份/生命周期不变时不重复注册任务，也不重新赋屏幕状态。
- `lib/rpc.js` 的 startServer 返回当前订阅的释放函数。Index、Workout、Summary 销毁时释放自己的 UI 闭包，保持 App 连接。只有订阅仍然匹配才清理，避免旧页销毁抹掉新页面订阅。
- App 记录 show/hide/error/destroy 及任务失败。诊断仍有原有大小和写入频率预算，不逐秒增加完整训练对象。

回看用户此前 2026-11-19 的系统日志归档，确有 RunningApp:com.zcode.gymtimer 和 software watchdog 同块记录，内部时间包含 2026-10-19、10-21、10-23 等旧日期，另有历史 UI_TASK 栈溢出。该归档混有多个日期与固件，不能断言当前 0.6.39 的无操作回表盘完全等同这些故障。本版不声称仅做亮屏或后台配置就消除了固件看门狗。

## 回归与真机验收

`frontend/src/lib/watch-background.test.js` 执行真实 app.ux、training-runtime 与持久化源码，替换硬件 API。覆盖非休息训练亮屏、App hide 检查点、HR 高频写入去重、暂停/关闭/冻结后的取消、等待写盘失败、任务迟到/重复/旧分段、进程重建、任务已满、回调丢失、任务元数据写失败、读失败、屏幕 API 失败和六小时边界。RPC 生命周期测试覆盖旧订阅不能释放新订阅，以及只注销 Page 不停止 App 连接。

真机步骤：

1. 覆盖安装配套版本。活动训练停在当前组，保持十分钟无触控；分别在概览、当前组、动作列表、休息页验证。记录是否亮屏、是否回表盘；暂停或结束后确认亮屏保持释放。
2. 手动返回表盘或打开其他应用，保持两分钟、十分钟和三十分钟。检查训练不被业务逻辑结束、前台显示不被抢回。重新打开后核对组、重量次数、休息绝对截止及统计是否正确恢复。
3. 有真实心率采样时退后台，在页面隐藏日志附近检查尾部数据写入。检查每次有效后台任务后只有新的单次任务，不存在快速重注册。
4. 开始 A 训练后退出，再保存或放弃 A 并开始 B；使 A 的延迟任务回调到达，确认 B 不受影响。暂停和关闭后也要验证。
5. 断连、低电量、省电模式及关闭屏幕分别测试。系统拒绝任务时应有失败记录，训练操作仍能继续；重新前台后可重试注册，不伪造保活成功。
6. 再出现无操作回表盘时，导出本版应用诊断和相同时间段系统日志。以 app_hide、app_destroy、app_error、重启时间与 native watchdog 对照判断；没有本版真机采样时，不填写实际退出率、CPU、FPS、内存峰值或功耗数字。
