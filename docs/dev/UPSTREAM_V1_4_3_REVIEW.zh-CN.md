# 官方 v1.4.3 定向评估（2026-10-27）

## 范围与结论

只比较官方 v1.4.2 → v1.4.3，不以我们自定义的 1.6.5 版本号判断功能是否包含，也不把更早分支的全部差异算作待合并内容。

- 官方 v1.4.2：`e9a303877d02e4237b183f96a9a6603990e8fafb`。
- 官方 v1.4.3：`7c8290ca20cb619bf6baa6830ea864d283df305a`，发布日志日期 2026-10-26。
- 来源：上述 Git 对象中的 CHANGELOG.md、相关提交补丁，与本地源码逐项对照。
- 本轮只评估，不 cherry-pick、不修改运行代码、不编译、不打包、不安装、不提交或推送。
- 下列“需适配”表示建议移植行为，不表示补丁可以直接应用。补丁不等价也不等于功能完全缺失。

## 第一批：建议优先同步

|优先级|官方变更 / 提交|本地核查|建议|
|---|---|---|---|
|P0|Android 更新安装入口收紧 `d7152f87a`|本地 InstallPlugin.java 仍只判断文件名非空，sha256 为空会跳过校验|必须移植文件名白名单与必需的 64 位十六进制 SHA-256；官方放在 src/sideload，我们在 src/main，不能直接套路径。校验和提供完整性保护，不应将其单独表述为签名可信验证。|
|P0|备份目录权限和文件清理边界 `b3d7dda51`|本地 prune 仍编译 JS 提供的 pattern；写入/清理入口缺官方新增的授权门禁|仅允许仍持有持久写权限的目录；写入与删除固定限于本应用日期备份名，避免误删其他文件。|
|P0（部署服务器时）|手机配对需重新证明身份 `de52c43f1`|本地 POST /api/pair/create 只有 readSession，未调用 proveOwner|服务端和前端配对流程、错误提示与测试一起移植，避免只改 API 导致手机配对不可用；Settings.jsx 有本地修改，应按功能移植。|
|P1|Android 下载更新后回前台再开安装器、复用下载、清理旧包 `2479b4b50`|当前安装插件立即 startActivity|与安全补丁配套；保留我们更新源、包名、签名规则，不能改回官方发布地址。|
|P1|Android 底部根标签不堆积返回历史 `c0411b05e`|本地 TabBar 的根标签仍直接 nav('/home') 等|连同 back.js 和导航测试一起适配，防止返回键绕回多个根页面。|
|P1|休息计时仅在状态改变时持久化 `a2aa6abdc`|本地 saveRest 会随 timer 变化重复 setItem|值得移植以减少倒计时写入；必须保留我们的 restId、startedAt、seq，不能用官方较少字段覆盖本地同步协议。这不是已证实的 1–2 秒链路延迟根因。|
|P1|旧休息通知先关闭再显示新通知 `39b80c6fb`|本地 showNotification 前未 getNotifications/close|小而独立，建议采用并保留通知回归测试。|
|P1（使用健康同步时）|导入体重不回写 Apple Health / Health Connect `a7fdd4cf1`|mergeImport 的体重分支未补 src:'import'|建议采用，配合核对当前健康写入过滤规则，避免历史导入被当成新称重重复写回。|
|P2|挂片重量提示不再译为次数 `c5c74cb32`|简体中文仍为“每侧 {0} 次”|改为“每侧 {0}”；不要误改代表次数的独立键 '{0}/side'。|
|P2|两个硬拉变式计入下背 `59a481118`|本地无该两条 SECONDARY_ADDITIONS|可小范围同步，含肌肉映射测试。|
|P2（使用相应模型时）|严格 JSON schema 400 的单次兼容重试 `9f534a033`|本地已有不带 JSON mode 的回退，尚无这套 strict-schema 处理|保留我们教练适配器的自定义逻辑，整体核对重试顺序与次数后再移植，不替换整个适配器。|

这些候选均核验属于 v1.4.2 → v1.4.3 区间，不是从更早版本翻出的积累改动。

## Apple Watch：我们手表可参考的部分

|1.4.3 行为|我们当前对应情况|采纳方式|
|---|---|---|
|自动切动作后 1 秒防误触 `5b81e81f9`|完成组会推进动作，需防止慢双击落到下一动作|最值得优先借鉴。只锁自动切页后的完成类操作；手动切页不应整页僵住，并验证超级组/单侧动作。|
|组页面可登记 RPE/RIR，随完成事件一起提交 `83a9221b9`|本地已有训练页入口与 sid + entryInstanceId + setId 的目标锁定修复|原则一致，不重复重写。继续保留“当前组草稿、未选择不登记、切组不串值”；本地独立 effort 事件也支持事后修改，不能为了照搬一并删掉。|
|3–2–1 等心率传感器预热，可点击跳过 `99b1f6179`|可用于第一组心率缺样的体验优化|先验证我们心率启动实际耗时，仅借鉴可跳过倒计时，不硬搬 HealthKit。|
|闲置 20 分钟询问、45 分钟自动结束，重启后仍检查 `acd74d913` 等|可防忘记结束训练导致时长过长|借鉴询问与恢复检查；自动结束应适配我们暂停/休息规则并可配置，不建议直接复制阈值和无确认结束。|
|手机丢弃训练时，手表不再保存为已完成训练 `19015f314` 等|跨端结束/丢弃需区分语义|优先补双向丢弃、离线重连、重复事件的回归用例，确保不误存。|
|手机完成的组也有手表心率 `533dcbf46`|双端操作都应有一致的组数据|可参考，先确认我们已有组时间窗采样是否覆盖，无需重复实现。|
|更清晰的 Done、较大数字、腕下低干扰显示 `39c13c939`|训练/休息 UI 已有本地优化|采纳信息层级与触控面积，不照搬 SwiftUI、Digital Crown、Water Lock。|

同步边界：官方依赖 WCSession.transferUserInfo 的系统队列；我们的 BlueOS 是持久 outbox + eventId 业务 ACK + 提交版本/组标识。应保留本地机制，不能把 Swift 的传输与按时间戳/组序号合并规则替换进来。官方 1.4.3 不等于提供了能直接解决我们延迟/回跳问题的通用补丁。

## 第二批：有价值但不宜混入修 bug

- CSV 训练/身体数据导出与回导 `6b7190278`：实用且相对独立，适合以后单独合并。
- 临时替换为预设备用动作 `3a8665f17`：适合器械被占场景，但须保留本地稳定动作/组标识及手表同步。
- 单动作“无计时”、单组休息、平板支撑等默认计时、单侧动作默认方式：有价值，但影响手机和手表共同的训练配置，必须成组适配并回归，不能只搬 UI。
- 热身组计入容量：贯穿训练、历史、统计、报告、教练，不建议零散抄字段。
- 训练计划肌肉缩略图、器械不规则配重档位：按需求安排，不是当前同步修复的必要依赖。

## 暂不优先

- 万圣节主题、iPhone 图标等装饰功能。
- Apple Water Lock、Digital Crown、HealthKit/Live Activity 原生代码不能直接用于我们的手表。
- 旧 iOS 启动兼容修复 `70a74ee7a` 与 iOS 配对令牌禁备份 `92cb1b3ff`：若仍支持 iPhone 发行，则应单独优先处理；若当前只发布 Android/BlueOS，不混入本轮首批。
- 到馆地理围栏提醒、Health Connect 一年历史读取：涉及原生权限/电量/兼容测试，另立需求。

## 建议顺序与验收

1. 安全补丁：安装器、备份目录、服务器配对；每项保留拒绝非法输入/未授权请求的测试。
2. Android 更新生命周期、返回键；保留我们的分发与签名，做前后台与根标签导航回归。
3. 休息写盘/通知、导入体重来源、重量文案；休息回归必须覆盖跳过后旧快照、暂停恢复和本地 restId/seq。
4. 手表自动切页防误触；RPE 保留已有修复，测试第一/第二组及训练/休息页面一致性。
5. CSV/备用动作等新功能另批决定，不与同步改动混成一次大合并。

本轮只做代码/补丁评估，未声称上述功能已合并或通过运行测试。已有手表与手机未提交修改保持不变。DeepSeek 汉化执行不属于本轮范围；动作要领方案与名称本土化也不应为了升级一起盲目覆盖。
