## 代码中复现的缺口及改动

1. **应用退出清理不完整。** 原 `app.onDestroy` 只停止心率，不停止 RPC 和应用级定时器。生命周期测试复现了销毁后迟到的 storage 成功回调继续发起下一次 SDK 写入。现停止通信服务、释放页面订阅、取消 App 定时器、结算未确认存储事务，并屏蔽停机后的 native 回调。训练记录和可靠队列仍在磁盘。
2. **开练消息冗余且缺少上行分片。** 新事件移除重复展示数据，保留手机条目全部语义和稳定身份；旧可靠事件只在发送时投影，不修改原 eventId/依赖。手机与手表协商 `watchEventChunks` 后，大事件按实际 JSON UTF-8 包大小分片，应用预算每片 3000 字节、完整事件 128 KiB。3000 是保守实现预算，不是对 SDK 官方上限的断言。
3. **整事件可靠性。** 分片在手机原生层有界重组，校验完整性和事件身份后才写既有持久化 Inbox。手机进程在半包阶段退出时，手表仍持有原事件并整包重发；片级 SDK 成功不会清队列。依旧只有精确业务 committed 才确认训练操作。
4. **圆点切组等待写盘。** 原流程合并点击后仍等 session 原子写成功才更新界面。现立即显示本地游标预览，持久化在后台确认；失败或离开恢复有效状态。完成/撤销继续核对稳定组身份与点击时的操作意图，防止把操作应用到邻组。
5. **手机端额外阻塞点。** Inbox 垃圾清理移到持久化决策之后异步执行，避免丢失的桥接回调阻塞导航和业务回执。这是注入测试证实的独立缺口，不是本次日志中 SDK param error 的解释。

日志输出还将错误码和实际包字节数移到长事件身份之前，避免被固件单行截断而丢掉最有价值的错误信息。

新增先失败再通过的存储/生命周期、大小拒绝 SDK 模型；覆盖部分发送失败、重连、手机进程丢失半包、重组重复/乱序/损坏、Inbox 写盘失败、延迟写盘期间的连续切组与完成/撤销。Java 侧重组、Inbox 和发送门的 14 项独立 JUnit 测试通过。完整前端、手机启动、API、编译与发布结果另见本版发布记录及 CI。
