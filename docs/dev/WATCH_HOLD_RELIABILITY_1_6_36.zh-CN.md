# 长按结束恢复边界补充

最终配套手机 1.6.36（82）、390×450 方屏 0.6.39（54）。

## 累积修复

本版保留 [1.6.35 的根因、回归和真机验收说明](WATCH_HOLD_RELIABILITY_1_6_35.zh-CN.md) 中的全部修复：重复 start、截止回调丢失、组提交在途与排队、本地保存和上传解耦、运行中关闭日志分批回放、满队列退避、冻结后的存储失败重试，以及连接文字仅首页显示。

在最终恢复路径检查中新增故障注入测试：先让 summary_last 写入失败，训练页保留冻结关闭提示，再通过真实 recoverLocalClose 模拟 App 后台完成恢复。此时 session_state 已清空，旧页面再次提交关闭会收到 session_changed；原训练页据此显示未结束并停留。该用例修改前失败。

`watch-app/src/Workout/index.ux` 的 onEnd 现在只在以下证据全部匹配时，将这次失败调用识别为同一关闭已完成：Page 原有冻结意图、当前没有活动训练、closed_sessions 包含原 sid、关闭日志标记 localClose 且 closeEvent.eventId 相同，以及保存场景的 summary_last.sid 相同。随后复用原日志导航到结果页，不新建事件、不重算汇总。

新增三个反例分别移除关闭标记、替换关闭 eventId、替换本地结果 sid；均不能把其他记录当成保存成功。页面仍按日志中的实际 disposition 决定导航位置。

## 验证与实机范围

新增真实 .ux / 原生 Page 代理契约测试在 `frontend/src/lib/watch-finish-hold.test.js`。继承修复曾通过本地全量 6474 项和 GitHub 完整验证；恢复边界新增四项后，需以本版提交对应的最终定向回归、CI 和发布校验记录为准，不能直接借用上一包的签名或通过状态。

原生重新编译方屏包，验证版本与签名，并对 390×450 编译模板和 SDK 字体生成的 87 个场景重新检查。没有真实固件触控或蓝牙采样，不声称已量化耗时、FPS、内存或死机率。
