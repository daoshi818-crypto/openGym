## 2. 必须实现的产品行为

### 2.1 今日计划、选计划、手表发起训练

1. 手机 App 前台打开或与手表通信时，手表首页可显示今日计划。计划需有稳定 ID、名称、动作数量及可开始状态。没有今日计划时显示清晰的空状态。
2. 手机端允许用户**手动选择要发送到手表的计划**；已发送的计划在手表端可浏览、选择和开始。手表不承担完整计划编辑。
3. 手表打开应用时主动请求最新计划和训练状态。手机在后台但进程和 RPC 仍可用时应响应。手机进程被系统清理时，手表显示上次缓存计划并标记“待同步”；不能承诺实时收到手机的新计划。
4. 用户从手表开始计划时，手表先创建本地会话并发送带唯一事件 ID 的 `watch_start`。手机收到后创建或恢复对应活动训练，回送权威会话 ID 和快照；重复请求不得产生两场训练。离线时手表可继续记录，重连后补传开始事件及训练事件。
5. 手机和手表同时只能有一场活动训练。若另一端已在训练，显示“继续当前训练/返回”，不得悄悄覆盖会话。

### 2.2 结束与放弃

手表训练操作页同时提供两个不同入口：

| 操作 | 用户流程 | 本地与手机结果 |
|---|---|---|
| 结束训练 | 显示“保存并结束 / 结束但不保存 / 继续训练” | 保存时生成最终总结并写入/覆盖同一手机训练记录；不保存时结束会话但不创建或覆盖训练记录 |
| 放弃训练 | 单独入口，二次确认“放弃本次训练并丢弃记录” | 立即关闭当前未保存会话；不生成训练记录或训练总结 |

“结束但不保存”可以展示一次性的结束反馈；“放弃训练”直接退出。两者都必须把**关闭会话的事实**同步到另一端，避免重连后旧计划/旧快照重新激活训练。可用 `session_close` 事件，含 `sid`、`disposition: saved | discarded | abandoned`、`eventId`、`closedAt`；只有 `saved` 附带热量、时长、完成组等总结。手机或手表离线时持久化关闭事件和会话墓碑，重连后重发直到确认，且旧 `plan`/`sync` 不得复活已关闭的 `sid`。若曾经保存过这场训练又继续训练，之后选择“不保存”或“放弃”时，不得删除先前已保存的历史记录；只丢弃这次续练的未保存增量。

### 2.3 手表本地编辑立即生效

- 手表修改**重量、次数、组数**后，立即更新画面与本地持久化，再异步发送对应事件；不等待手机确认才显示新值。手机端按事件 ID 幂等应用，回传快照时不得把较新的手表编辑覆盖回旧值。
- 组数指当前动作的计划/实际组行数量。加组、减组立即改变手表列表及组号；不得删已完成组或最后一组。若业务允许删除已完成组，须先显式撤销其完成状态。
- 已完成组明确标为已完成，“完成本组”按钮不可再次提交；需要重新做时通过单独的撤销动作。
- 手表离线期间的重量、次数和组数编辑必须保留。重连后补传可靠事件；手机应用这些编辑后再发包含确认版本的快照。冲突按每组字段的事件顺序/版本处理，不用整场快照简单覆盖。

### 2.4 动作与组导航修复

当前现象：手表“动作”页能看到本场所有动作，但从动作 A 选择动作 B 第 2 组后，训练页很快被切回 A。要求：

- 点击某动作某组后，训练页立即显示该动作/组；保持在用户所选位置，直到用户再次手动切换、明确跟随手机导航，或该动作/组被删除。
- 将**训练数据**（组完成、重量、次数、计划结构）和**浏览游标**（当前查看的动作/组）分开。普通 `plan`/`sync` 只更新数据，不能无条件重置手表游标。游标只接受显式 `focus` 事件；每个焦点事件应带来源、时间/递增序号，忽略过期事件和本机事件回显。
- 手机当前训练动作可随手表的显式选择切换；手机没有组级游标时，也不能在下一次快照用“第一个未完成组”覆盖手表主动选择的组。
- 动作/组被删除时游标才按边界调整到最近仍存在的组。切换浏览位置本身不应改动完成状态、休息状态或重量/次数。

### 2.5 本次休息总时长与剩余时间

手机和手表休息界面必须**同时、明确标注**：`剩余 1:15` 和 `本次休息 1:45`。这里的“本次休息”是当前这一轮的目标总时长，不是整场训练的累计休息时间，也不是当前剩余时间。

例子：默认休息 1:30，经过 0:30 后剩余 1:00；此时加 0:15，显示应立即变成 **剩余 1:15 / 本次休息 1:45**。再减 0:15 则回到 **剩余 1:00 / 本次休息 1:30**。两端调整都必须同步这两个值。

数据模型建议每轮保存 `restId`、`startedAt`、`endsAt`、`totalSec`、`seq`。`remainingSec = max(0, ceil((endsAt - now)/1000))`；调整 `+/- delta` 同时更新 `endsAt` 和 `totalSec`，不重置 `startedAt`。暂停、息屏恢复、重启和重连后根据绝对时间重算剩余值。跳过/结束休息时两端清除本轮状态。跨端 `rest` 消息必须发送真实 `totalSec`、剩余时间或截止时间及 `restId/seq`，防旧消息回放；手机已保存的默认休息设置不应因本轮加减而改变。表冠连续旋转应节流发送/落盘但每次旋转即时更新显示，防止再次卡死。

现有缺陷定位：手表 `Workout/index.ux` 的 `restTotalLabel` 目前显示的是 `session.js` 里 `restTotalSec`（**整场累计休息**）；手机 `watch-link.js::pushRestToWatch` 把 `totalSec` 错填成 `leftSec`；手表 `flushRestNudge` 也把 `totalSec` 填成 `left`。手机 `useUI` 的 `timer.total` 已有当前目标总时长，应作为接线基础。

### 2.6 手机训练页快速唤起手表

在**正在进行的训练页**现有标题/操作区域加入一个小而明确的手表图标按钮，视觉和原有按钮、间距、字体一致；有 tooltip/无障碍名称“在手表上继续训练”。点击后调用现有 `openWatchApp()`，确认 RPC 已初始化，拉起手表应用并补发当前 `plan` + 最新 `sync`；不能因点击重复创建训练。给出连接中、请求已发、手表确认、未连接/失败等状态；`code=0` 只代表拉起请求被 SDK 接收，实际成功以手表 `hello`/回执为准。非 vivo 或无健康 App 时按现有能力检测显示不可用提示，不在网页端做无效操作。

### 2.7 其他优先完善的手表能力

1. 暂停/继续训练，计时和休息状态双端一致。
2. 明确显示“已连接 / 正在同步 / 离线记录 / 待上传 N 条”；结束页显示最终上传状态。
3. 会话和 outbox 持久化，应用重启后恢复未结束训练；重连按事件 ID 幂等补传。
4. 手机结束训练而手表离线时，重连后手表必须关闭对应会话；反方向也一样。
5. 已完成训练继续训练时沿用同一记录 ID、累计时长和热量，下一次保存覆盖该记录；不另建重复记录。
6. 休息结束震动；心率与热量在可用时记录，并标注热量为估算。息屏期间计时按绝对时间恢复，不能依赖 UI 定时器次数。

8. 可查看本次训练概览、最近一次结果及同步状态；基础设置可包含默认休息时间和重量调整步长。设备电量/连接状态可在有数据时展示，不阻塞核心训练。

## 3. 协议与可靠性建议

- 沿用现有 `plan`、`sync`、`hello`、`set`、`unset`、`weight`、`reps`、`add_set`、`remove_set`、`rest`、`focus`、`end/summary` 的 RPC 通道，增量增加 `plan_catalog`、`plan_select`、`watch_start`、`watch_start_ack`、`session_close` 及各自回执。不要切换到旧 BLE 直连草案。
- 所有改变训练记录的事件携带 `sid`、唯一 `eventId`、来源、时间和递增版本。发送方先本地持久化再发送；接收方幂等应用后确认；断连重试不能重复完成组或重复保存。
- 计划 ID 和会话 ID 分开。计划选择不等于开始训练；`watch_start` 被手机确认前手表可离线继续，但要显示待同步。手机创建活动会话时应与手表既有本地会话对齐。
- 保存、结束不保存、放弃属于不同关闭意图；重连时优先处理关闭墓碑，再处理旧计划/训练事件。已保存记录的续练更新使用稳定记录 ID。
- 可靠的后台能力分层验收：手机进程在后台仍存活时实时响应；进程被系统杀死时手表可读缓存、离线记录并在手机恢复后补传。若要唤醒已被杀死的手机进程，需原生 Android 接收/恢复机制和 vivo 真机测试，不能仅依赖 React 页面监听。

## 6. 推荐开发顺序与验收

1. **先修现有训练正确性**：手表动作/组选择保持、重量/次数/组数立即生效且不回退、当前休息总时长和剩余时间双端正确显示。为这些状态和重连旧快照写专项测试。
2. **补完整会话结束语义**：手表“保存并结束 / 结束但不保存 / 放弃训练”、手机同步关闭、离线重连墓碑、已保存训练续练后的覆盖逻辑。
3. **训练页快速唤起**：入口融入原界面，使用现有 `openWatchApp`，基于 `hello` 和业务回执显示实际结果。
4. **计划目录和手表发起训练**：手机选择并发送今日计划，手表选择、开始、手机创建活动会话，处理后台存活/离线/重复请求。
5. **体验收尾**：暂停继续、同步状态、恢复、表冠/震动、总结、手表 390×450 适配；同步更新双端版本号、更新检测信息，构建并真机验证后再推 GitHub。

核心验收场景：

- 手表动作页点动作 B 的第 2 组，返回训练页 10 秒及一次 `plan`/`sync` 后仍在 B-2；手机若同步焦点，也不能把它反推回 A。
- 手表加组、减组、改重量/次数后立刻显示；断网重连、旧快照到达、应用重启后数值不回退；已完成组不能重复完成。
- 从 1:30 的本轮休息在剩余 1:00 时加 15 秒，手机与手表均显示“剩余 1:15 / 本次休息 1:45”；息屏、重连和表冠连续旋转后仍一致。
- 手机训练页一键拉起手表，收到 `hello`/同步回执后手表显示同一训练；重复点击不新建会话。
- 手表“保存并结束”生成一条完整手机记录；“结束但不保存”和“放弃训练”均不生成新记录，且重连后不复活。离线结束时关闭意图最终能同步。
- 手机后台存活时打开手表可看到今日计划并从手表开始；手机被杀后手表可读缓存并离线记录，恢复后只生成一场手机会话且数据无重复。
- 已完成训练继续训练后再次保存时覆盖原记录，累计时间及热量不归零。
