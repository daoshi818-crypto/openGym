## 4. 评分交互的确定方案

从休息页入口打开训练页内的全屏覆盖层，使原训练页、计时器、RPC及心率 owner 保持运行。避免新增页面后 onHide 停止计时刷新/到期处理的问题。

```text
‹ 返回          休息 01:23
卧推 · 刚完成第2组
             RPE

       ‹   7.5  [8]  8.5   ›
           左右滑动选择

        还能再做约2次
       保持同样动作标准

           [确认登记]
```

### 数字选择规则

- 左滑数值增加，右滑减少；每次有意滑动移动一个0.5步长，边界不循环。
- 两侧箭头为可点击备选，避免滑动识别困难；表冠在评分层内只调整评分，不再调整休息或切组。
- 中央数值与中文解释同步更新；拖动中不写盘、不发消息，确认时提交一次。
- 初次打开为“— / 左右滑动选择”。第一次选择从量表最低档开始，并立即显示中文含义；不默认推荐RPE 8或沿用上一组。
- 编辑已有评分时显示已存值。手表中途接收手机量表变化时，保持当前编辑所捕获的量表并提示已变化；确认前要求重新打开，避免按新量表错误保存旧数字。
- 取消保留原值；已评分时提供单独的“清除登记”。0 RIR是有效评分，不等于清除。
- 旧数据若有非0.5步长或常用范围外的有效评分，应如实显示，并允许取消/清除；不在打开界面时静默截断历史值。

### 中文含义

与手机现有“剩余次数”表达保持一致。下列RPE/RIR关系是应用当前的近似换算说明，不宣称生理测量精度。

| RPE显示 | RIR显示 | 中文主说明 |
|---|---|---|
| 10 | 0 | 无法再完成一次标准动作 |
| 9.5 | 0.5 | 可能已做不完下一次 |
| 9 | 1 | 还能再做约1次 |
| 8.5 | 1.5 | 介于还能做1次与2次之间 |
| 8 | 2 | 还能再做约2次 |
| 7.5 | 2.5 | 介于还能做2次与3次之间 |
| 7 | 3 | 还能再做约3次 |
| 6.5 | 3.5 | 介于还能做3次与4次之间 |
| 6 | 4 | 还能再做约4次，较轻松 |
| — | 4.5–10 | 显示实际数字及对应剩余次数；半次值表达为相邻整数之间 |

本次滑动选择器记录确切数值，不将4+范围标签冒充精确值。既有手机快捷4+仍按原规则记录4，不修改手机历史与原功能。

### 不打断休息的状态规则

1. 完成本组时捕获 `{sid, entryInstanceId, setId, completedAt}`；休息条始终表示这组，不受随后焦点跳到下一组影响。
2. 打开、滑动、确认、取消评分都不调用暂停、重启休息，也不改写 restUntil/restVersion。
3. 每次刷新读取最新休息状态，显示 `max(0,ceil((restUntil-now)/1000))`。手机增减时间/暂停/跳过仍照常生效。
4. 登记中到期：只提示/震动一次，顶部显示“休息已结束”；保留评分草稿，用户确认后回到现有下一组界面，不自动开始训练。
5. 评分提交只合并目标组评分字段到最新状态，不能保存打开时整份旧state，防止恢复过期休息或覆盖手机同步。
6. 训练结束、目标删除或被撤销完成时关闭编辑并提示目标已变化；不能落到当前下一组。
7. 最后一组保留现有保存/继续选择，在该面板增加“登记本组强度”入口；评分期间原休息仍可自然到期，确认后回到该面板。未评分不阻止保存。
8. 无休息或直接跳过休息，不强制制造一轮休息；可通过已完成组入口补录。零休息不改为强制评分。

## 5. 手表与手机数据技术方案

建议抽出纯函数共享定义（拟议路径 `shared/effort-scale.js`，需结合仓库构建允许范围确定最终目录），包含范围、步长、近似说明和合法性校验；手机现有effort helper引用该定义。手表中文短文案可以独立映射，但数值规则一致。

协议采用能力声明，例如 `capabilities.setEffort:1`，不以当前手机版本字符串猜支持。计划/目录/重连快照携带 `effortScale:'none'|'rpe'|'rir'` 与配置版本；离线沿用最后已确认配置，新设备无配置时隐藏入口。旧端明确标记不支持，不能显示“已同步”。

拟议事件：

```json
{
  "t":"effort", "sid":"...", "entryInstanceId":"...", "setId":"...",
  "scale":"rpe", "value":8, "clear":false,
  "eventId":"...", "seq":123, "at":123, "baseEffortVersion":"..."
}
```

- 每组存rpe或rir其中一个；明确更换评分时清除该组另一字段，普通快照缺字段不等于清除。
- 新增组不继承上一组评分，重做被撤销的组不隐式继承旧评分。
- 评分有独立版本域，不能复用done/weight/rest版本。优先沿用同步引擎可靠的字段版本规则；不能只按双方时钟先后判断跨设备冲突。
- 相同eventId重发幂等；目标被删/会话关闭时明确拒绝；基于旧评分版本的离线编辑遇手机修改，返回冲突与现值，避免静默覆盖。
- 评分先入现有持久队列再发送；ACK之后才显示已同步。没有连接时提示离线记录，不能阻止继续训练。
- 计划快照、实时事件、重连合并、session_close/end的completedSets、离线恢复均保留评分及清除版本；旧摘要不能复活已清除评分。
- AI教练已读rpe/rir字段，验证新数据进入单次/计划复盘，不额外推断未填组。

涉及：watch `Workout/index.ux`、session/protocol/rpc；手机 `watch-workout/watch-events/watch-session/watch-recovery/watch-link`，及现有训练字段广播。具体新增函数和文件名实施时定位，不将文档中的拟议接口当作已存在。

## 6. 手机卡片悬浮窗迭代

保持Android原生悬浮窗只在离开APP且有休息时显示；回到APP收起。卡片样式改成紧凑信息条，现有圆环样式保留。先解决信息和占位，复杂操作分层增加。

### 默认紧凑态

拟议宽224–248dp、高76–88dp，按可用窗口宽度和系统字号自适应，不把固定高度作为裁切条件：

```text
 01:23   下一组 · 卧推       ⌄
 休息中  第3/4组 · 60kg × 8
 ━━━━━━━━━━━━━━━━━━━━━━━
```

用左侧倒计时和右侧训练摘要替代纵向标签胶囊；进度线约2dp。数字约28sp，正文14sp，次级12–13sp；大字体可增高。点击主体继续回APP；独立展开区负责展开；拖动热区与按钮互不抢事件。

不常驻总容量、总训练时间、心率、热量及RPE编辑器。当前原生休息服务没有可靠的实时全训练数据来源，首先展示确切下一组摘要。无法确认下一组时显示“返回训练查看”，不编造。

### 展开态

约248dp宽，高度随文字变化。展示完整动作名、下一组处方、可选刚完成组的已登记强度，再提供暂停/恢复、−15、+15、跳过。整块按钮保留足够可点区域；横向四个48dp操作在布局中有余量，必要时两行，不靠缩小文字塞入。

第一批先交付紧凑态与信息模型；第二批再加展开操作。主体点击回APP行为保留，只有明确展开区域改变展示。不直接在悬浮窗完成训练组或编辑RPE，避免扩大本轮训练记录入口。

### 数据与生命周期

- 新建纯helper（拟议 `rest-context.js`）：从最新active及休息归属计算刚完成组与下一组。沿用现有超级组/双侧/动作切换规则，不以简单index+1代替。
- 摘要含 `{version,sid,restId,contextRevision,nextEntryId,nextSetId,name,setNumber,totalSets,unit,weight,reps|seconds,effort?}`；只发送展示必需字段和翻译后的短标签。
- 扩展 rest-alert→RestAlertPlugin→RestAlert→RestTimerService→RestOverlay 的结构化数据；新增context更新方法，只更新内容，不重新安排闹钟或改变截止时间。
- 首次开启休息、焦点/组状态/处方变化、手表同步后按数据版本更新；后台JS冻结时，原生持续计时，最后已确认摘要标记版本。无法及时更新时允许隐藏处方，不能宣称实时。
- 新增的暂停/加减/跳过命令绑定sid/restId/requestId，串行执行，旧轮次命令不能影响新休息。原生服务负责后台倒计时，APP恢复时读取最新状态，旧WebView状态不得反向重启已结束休息。
- 暂停文案明确显示“已暂停”，不继续冒充倒计时；到期沿用当前提示和移除规则，不另加常驻完成悬浮窗。
- 当前overlayStyle只在设置变更时下发，需在启动/恢复/开始休息时恢复持久设置，避免进程重启回默认卡片。
- 拖动位置按可用窗口和系统遮挡范围限制；旋转、键盘、分屏及字体变化后重算，不能拖出屏幕。隐藏仅隐藏本轮窗口，闹钟与训练照常。
